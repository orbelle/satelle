## [1.0.79] - 2026-11-16

### Added
- `satelle doctor` reports a project of this machine whose path no longer exists (check `projects`, fix `satelle project remove <path>`), and `satelle doctor --resolve` removes it from `~/.satelle/config.toml` [projects] without asking (sto_fd7a61e4)

### Changed
- The volatile-fact scan reads only the files `.satelle/volatile.toml` names under `paths`; the shipped volatile.toml declares the `.satelle` Markdown scope (`paths = [".satelle/**/*.md"]`). A repo whose volatile.toml has `paths = []` adds that glob to keep scanning its `.satelle` Markdown (sto_13698e1e)
- The sync pass (`satelle ledger autosync`) removes a gone project only by running doctor's `projects` check and its fix, not a rule of its own (sto_fd7a61e4)
- The tests that guard the shipped satelle-reference-not-restate principle read its sentences from the template instead of restating them in Go, so rewording the principle needs no Go change; a test now fails when either principle test restates one of its sentences (sto_ff0d6284)
- The exceptions to the rule that every satelle command a session doc shows names `--session` live in `.satelle/session-exceptions.toml`, which the session-docs test reads, instead of a Go slice in the test (sto_f1ef3849)
