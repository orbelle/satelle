## [1.0.148] - 2026-11-27

### Added
- The release tests run the node with go off its own PATH and on the suite path, proving the binary decision derives the build set there and fails safe with a reason when go is on neither (sto_7c865ab5)
- A judge binding may name `fallback = "<agent>"`: when its dispatch fails (the judge could not be asked), satelle asks the fallback with the same prompt and records its verdict, with the first binding and its redacted error under `fallback_from` on gate.run; validate refuses an unknown, self, chained, non-judging or same-gate fallback, and the judge-differs check requires a judge's fallback to differ from the performer too. (sto_eef1d36a)
- A queue's `[trigger]` can set `overlap = "allow"` so a fire starts a new run while earlier runs are open, taking only the members no open run took; the default stays `refuse`. (sto_6f2ca725)
