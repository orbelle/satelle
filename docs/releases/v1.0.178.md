## [1.0.178] - 2026-11-28

### Changed
- The edit gate judges a shell command's write targets, and a file tool's path, as written, as the entry they name and where they land through symlinks (a dangling link and `..` after a link included), so a redirect, cp, touch or git commit through a link in a seated target that points into the control repository or another checkout is refused, naming where the link resolves. The gate no longer follows cd for writes: a line that holds cd, pushd or popd together with any write target is refused, naming the rule (use an absolute path or git -C); a line with cd and no write is judged as before.
