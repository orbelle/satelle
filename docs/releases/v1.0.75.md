## [1.0.75] - 2026-11-14

### Fixed
- The automatic sync pass removes a project whose path no longer exists from this machine's projects (`~/.satelle/config.toml [projects]`) and removes its satelled partition, so a deleted or temporary project no longer stays on satelled's projects page; a satelled that is not answering removes no partition. (sto_e3c6bfb6)
- `make test` and `make integration` fail, naming the files, when a test writes `~/.satelle` instead of a home of its own. (sto_e3c6bfb6)
- By default, `make test` and `make integration` run the suite under `bwrap` with the caller's real satelle home mounted read-only, so the suite cannot write it by any route, and an absent home cannot be created; the Go caches and the source tree stay writable. (sto_e3c6bfb6)
- Where bubblewrap is missing or cannot run, `make test` and `make integration` refuse to run (exit 2) and say to install bubblewrap or set `SATELLE_HERMETIC_ALLOW_SNAPSHOT=1`. (sto_e3c6bfb6)
- `SATELLE_HERMETIC_ALLOW_SNAPSHOT=1` is an explicit, detection-only opt-in: the wrapper gives the suite no path to the caller's home (the Go toolchain, caches and starting directory reach it as stable symlinks under `/tmp/satelle-hermetic-<uid>`) and detects any change to that home, failing the run and naming the paths, with no path exempt. On a host where satelle itself is running (satelled, the sync timer, other sessions), an opted-in snapshot run can fail on that satelle's own writes; it is meant for a throwaway container, and the default bwrap mode does not have this problem. The wrapper names the mode it ran in on stderr. (sto_e3c6bfb6)
