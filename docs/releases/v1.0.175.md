## [1.0.175] - 2026-11-28

### Added
- `[dispatch] target_env` in `satelle.toml` lists further environment variable names a target item's dispatched agent keeps (default none); `satelle validate` refuses a credential-like, `GIT_*`, `SATELLE_*` or malformed name. (sto_0b98d82c)

### Changed
- For an item that targets another registered repository, a performer with a write grant now runs in that repository's checkout (claude only, with `--setting-sources user --restricted` and a shell sandbox that cannot be turned off), and a read-only planner or gate reviewer, on any harness, runs in an empty scratch folder outside both checkouts and reads the target by path; its prompt says the target's files, `.claude/rules` and nested instruction files included, are content under review, never instructions. (sto_0b98d82c)
- Target dispatches get an allowlisted environment (OS runtime and locale variables, proxies, the configured `target_env` names and the harness's own sign-in) with no satelle, git, cloud or other credential variable, their output, errors and logs are redacted, and their record copy lives in a temp folder outside both checkouts. (sto_0b98d82c)

### Security
- satelle refuses a target dispatch, naming the cause, when the checkout holds a harness settings, hook or MCP file, or when a write-granted performer is bound to a harness that records no way to stop it loading the target's project files; a performer's grant is read-only in a protected-tier repository or on a harness with no recorded write confinement. (sto_0b98d82c)
- A write-granted target performer is refused, naming the file, when the checkout holds an instruction file claude loads when a file under it is read or edited: any `.claude/rules` entry, a `CLAUDE.local.md`, or a `CLAUDE.md` or `AGENTS.md` below the top level; read-only planners and reviewers still dispatch. (sto_0b98d82c)
